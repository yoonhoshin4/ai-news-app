# 새 기능 개발 워크플로

새 기능 개발을 아래 단계 순서대로 진행한다. 각 단계가 끝나기 전에는 다음 단계로 넘어가지 않는다.

입력받은 브랜치 이름: `$ARGUMENTS`

## 1단계: 현재 상태 확인

1. `git status`와 `git branch --show-current`로 현재 브랜치와 작업 트리 상태를 확인한다.
2. 현재 브랜치가 `main`이 아니면 경고를 주고, main으로 이동할지 사용자에게 묻는다.
   - 사용자가 동의하면 `git checkout main`으로 이동한다. 커밋하지 않은 변경이 있어 이동이 막히면 변경 내용을 알려 주고 처리 방법을 묻는다.
   - 사용자가 거절하면 워크플로를 중단한다.
3. main이면 `git pull`로 최신 상태인지 확인한다 (원격이 있을 때만).

## 2단계: 새 브랜치 만들기

1. `$ARGUMENTS`가 있으면 그 이름으로 브랜치를 만든다: `git checkout -b <이름>`
2. `$ARGUMENTS`가 비어 있으면:
   - 어떤 기능을 개발할 것인지 사용자에게 묻는다.
   - 답변을 바탕으로 영어 소문자-하이픈 형식의 브랜치 이름을 제안한다 (예: `save-news`, `category-filter`).
   - 사용자가 확인하거나 수정한 이름으로 브랜치를 만든다.
3. 이미 같은 이름의 브랜치가 있으면 알리고 다른 이름을 묻는다.

## 3단계: 개발 시작 안내

1. 브랜치 생성이 끝나면 "이제 개발을 시작하세요!"라고 안내한다.
2. `CLAUDE.md`를 읽고 이 프로젝트의 기술 스택과 컨벤션을 다시 한번 알려 준다. 최소한 다음을 포함한다.
   - 기술 스택: Next.js 16(App Router, 학습 데이터와 규약이 다르므로 `node_modules/next/dist/docs/` 확인), Clerk 인증, Neon + Drizzle, Tailwind CSS v4, Claude Haiku, Notion MCP
   - 컨벤션: 모든 쿼리는 `userId`로 필터, 화면 작업 전 `ui.md` 읽기, 요구사항 기준은 `PRD.md`, 미들웨어는 `src/proxy.ts`
   - 자주 쓰는 명령: `npm run dev`, `npm run build`, `npm run lint`
3. 이후 사용자가 요청하는 개발 작업을 진행한다.

## 4단계: 완료 처리 (사용자가 '완료' 또는 'done' 입력 시)

사용자가 `완료` 또는 `done`이라고 입력하면:

1. `git status`와 `git diff --stat`로 변경된 파일 목록을 보여 준다.
2. 변경 내용을 바탕으로 커밋 메시지를 자동으로 제안한다. 이 저장소의 기존 커밋처럼 한국어로 간결하게 쓴다 (`git log --oneline`으로 스타일 확인).
3. 사용자에게 커밋 메시지를 확인받는다. 수정 요청이 있으면 반영한다.
4. 사용자가 확인하면:
   - 변경 파일을 스테이징하고 커밋한다. 그 전에 `.env*` 같은 비밀 파일이 포함되지 않았는지 확인한다.
   - `git checkout main`으로 이동한 뒤 `git merge <브랜치 이름>`으로 병합한다.
   - 병합 충돌이 나면 충돌 파일을 알리고 해결 방법을 사용자와 상의한다.

## 5단계: 작업 요약

병합이 끝나면 다음을 요약해서 보여 준다.

- 브랜치 이름과 병합 결과
- 커밋 메시지와 해시
- 변경된 파일 목록과 각 파일의 핵심 변경 내용
- 구현한 기능 요약 (무엇을 추가·수정했는지)
- 남은 작업이나 후속 확인 사항이 있으면 함께 안내
